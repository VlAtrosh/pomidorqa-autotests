# PomidorQA - автотесты

[![Playwright CI](https://github.com/VlAtrosh/pomidorqa-autotests/actions/workflows/playwright.yml/badge.svg)](https://github.com/VlAtrosh/pomidorqa-autotests/actions/workflows/playwright.yml)
![Tests](https://img.shields.io/badge/tests-42_passed-success)
![Coverage](https://img.shields.io/badge/coverage-80%25-green)

Проект автотестов для [PomidorQA](https://aiqa.su/pomidorqa) - сервиса коротких
25-минутных звонков для QA/IT-специалистов. Проверяет регистрацию, профиль, навыки,
слоты, поиск в каталоге, бронирование и отмену встреч.

## Быстрый старт

```bash
# 1. Установить зависимости
npm ci
npx playwright install chromium

# 2. Запустить все тесты
npm test

# 3. Посмотреть отчет
npm run report
```
## Команды

| Команда | Что делает |
|---|---|
| `npm test` | Все тесты (unit + API + E2E) |
| `npm run test:unit` | Только unit-тесты |
| `npm run test:api` | Только API-тесты |
| `npm run test:e2e` | Только E2E-тесты |
| `npm run lint` | Проверка стиля кода |
| `npm run report` | HTML-отчет последнего прогона |

## Переменные окружения

По умолчанию тесты идут на **https://aiqa.su**. Для локального стенда:

```bash
$env:POMIDORQA_BASE_URL="http://localhost:3000"
npx playwright test
```

## Архитектура

```text
tests/
├── unit/         - unit-тесты чистых функций
├── api/          - HTTP-тесты (регистрация, бронирование)
├── e2e/          - браузерные сценарии
├── helpers/      - фабрики данных и API-хелперы
└── pages/        - Page Object'ы

src/pyramid/      - вспомогательный код для unit и api
```

### Принципы

- **Подготовка данных** - через API (быстро), **проверки** - через UI (как видит пользователь).
- Каждый тест создает свои данные через `makeUser(role, Date.now())` и убирает за собой в `afterEach`.
- **Один браузерный контекст - один участник** (cookie сессии не пересекаются).
- В E2E - `test.step` с человеческими именами, `expect` в тесте, локаторы - в Page Object.

## CI

GitHub Actions запускает на каждый push и pull request в `main`:

- `npm run lint` - ESLint
- `npm test` - unit + API + E2E

**Прогон:** ~4 минуты, **стабильность:** 0 flaky на 3 прогонах подряд.

## Стратегия тестирования

### Unit

Чистая детерминированная логика — без браузера, без сети, без внешнего стенда.
Пересечение слотов, форматирование времени, валидация пароля.

### API

HTTP-контракты, где UI не нужен для доказательства правила: бронирование,
гонка за слот, отмена с окном 2 часа, регистрация.

**Локальный mock API** явно отделён от live API и не выдаётся за внутреннюю
реализацию production-сервиса. Mock-сервер — это часть тестового кода,
он работает в памяти и не требует внешних сервисов.

### E2E

Только интегрированные пользовательские сценарии, где важны:
- браузер
- реальная сессия
- состояние нескольких участников

**Кросс-браузерность:** основной E2E-набор выполняется в Chromium с `retries=0`.
Внутри browser job используется `workers=4`, чтобы не перегружать внешний стенд.
