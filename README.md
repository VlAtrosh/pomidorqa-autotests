# PomidorQA — автотесты

Проект автотестов для [PomidorQA](https://aiqa.su/pomidorqa) — сервиса коротких
25-минутных звонков для QA/IT-специалистов. Проверяет регистрацию, профиль, навыки,
слоты, поиск в каталоге, бронирование и отмену встреч.

## Покрытие требований

Покрытие считается от [спецификации](./docs/requirements.md) (50 функциональных
требований MVP). По методике урока 16 статус присвоен каждому требованию.

| Статус | Кол-во | Что значит |
|--------|-------:|------------|
| `automated` | 27 | Тест упадёт, если поведение сломается |
| `partial` | 3 | Покрыта наблюдаемая часть, серверная — нет |
| `known defect` | 1 | Продукт требование не выполняет, тест помечен `test.fail()` |
| `out of scope` | 2 | Состояние через интерфейс недостижимо |
| **не покрыто** | **17** | Требование есть, теста пока нет |
| **Итого** | **50** | |

**Покрытие: 27 из 50 — 54%.**

С подробной матрицей — [docs/coverage-matrix.md](./docs/coverage-matrix.md).

### Распределение по уровням

| Уровень | Кол-во | Что проверяет |
|---------|-------:|---------------|
| unit | 10 | Пересечение слотов, форматирование времени, валидация пароля |
| API | 11 | Регистрация, бронирование, гонка за слот, ошибки |
| E2E | 14 | Регистрация через UI, профиль, каталог, бронирование, отмена |

### Что не покрыто (17 требований)

Основные дыры — негативные пути и права доступа:

- **гостевой доступ** (R3.2–R3.4) — гость видит слоты, но не может бронировать
- **правила слотов** (R7.2, R7.4, R7.5) — нельзя создать слот в прошлом, удаление свободного слота
- **окно отмены** (R11.2) — запрет отмены позже чем за 2 часа до звонка
- **страница участника** (R9.2, R9.3) — скрытие занятых и прошедших слотов

## Быстрый старт

```bash
# 1. Установить зависимости
npm ci
npx playwright install chromium

# 2. Запустить все тесты
npm test

# 3. Посмотреть отчёт
npm run report
```

# QA-проект: автоматизация тестирования

## Команды

| Команда | Что делает |
|---|---|
| `npm test` | Все тесты (unit + API + E2E) |
| `npm run test:unit` | Только unit-тесты |
| `npm run test:api` | Только API-тесты |
| `npm run test:e2e` | Только E2E-тесты |
| `npm run lint` | Проверка стиля кода |
| `npm run report` | HTML-отчёт последнего прогона |

## Переменные окружения

По умолчанию тесты идут на **https://aiqa.su**. Для локального стенда:

```bash
$env:POMIDORQA_BASE_URL="http://localhost:3000"
npx playwright test
```

## Архитектура

```text
tests/
├── unit/         — unit-тесты чистых функций
├── api/          — HTTP-тесты (регистрация, бронирование)
├── e2e/          — браузерные сценарии
├── helpers/      — фабрики данных и API-хелперы
└── pages/        — Page Object'ы

src/pyramid/      — вспомогательный код для unit и api
```

### Принципы

- **Подготовка данных** — через API (быстро), **проверки** — через UI (как видит пользователь).
- Каждый тест создаёт свои данные через `makeUser(role, Date.now())` и убирает за собой в `afterEach`.
- **Один браузерный контекст — один участник** (cookie сессии не пересекаются).
- В E2E — `test.step` с человеческими именами, `expect` в тесте, локаторы — в Page Object.

## CI

GitHub Actions запускает на каждый push и pull request в `main`:

- `npm run lint` — ESLint
- `npm test` — unit + API + E2E

**Прогон:** ~4 минуты, **стабильность:** 0 flaky на 3 прогонах подряд.
